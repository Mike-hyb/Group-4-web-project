    How this page is protected

    In this demo (browser)

    Strong passwords (12+ characters, mixed types, no common words). MFA code after sign-in. A signed JWT (HS256, 15-minute expiry) kept in memory only, never in localStorage. Passwords hashed with PBKDF2 and a random salt. Loan data encrypted with AES-GCM. Lockout after 5 failed attempts. Idle sign-out after 5 minutes. All user text is shown with textContent, so injected HTML or script cannot run. Same error for wrong email or wrong password.

    What must run on a real server

    SQL injection: use parameterized queries or an ORM, never string-built SQL. MITM: HTTPS only, TLS 1.2+, HSTS header. DDoS: CDN or WAF, rate limiting per IP and per account. Phishing: phishing-resistant MFA (authenticator app or passkeys), SPF/DKIM/DMARC on your email domain. IAM: least-privilege roles, separate database user with no admin rights, secrets in a vault. Headers: Content-Security-Policy, X-Content-Type-Options, secure HttpOnly SameSite cookies.

    Important limits of this demo

    The "server" below runs in your browser so the page works as a single file. Browser code can be read and changed by anyone, so real checks (password hashing, JWT signing, MFA codes, encryption keys) must live on a backend. The MFA code is shown on screen only for the demo. Data resets when you refresh.
